# M03 architecture and coordinate contract

Python/NumPy/SciPy controller state → fixed-length articulated rig → depth-tested illustrated polygons/tubes and approved SVG head → fresh RGB frame → local FFmpeg H.264. No Blender render, Remotion footage, remote generation or paid API is used. Blender 4.3.2 is available if a failing subsystem needs general-purpose mesh/cloth simulation.

Units: metres, Y up. A character's unrotated forward axis is +Z, local right +X. `RY(heading)` places a rig in the world. Root, pelvis basis, torso/chest basis, neck and head share one skeleton; hip/shoulder offsets are local to their parent frames. Thigh/shin lengths are .37m each and upper/lower arms .34m each. Two simplified finger phalanges are .034m each. Reach failure raises an error rather than stretching geometry. The pelvis lowers to remain inside the leg-reach envelope; it does not pull planted feet off the floor.

Knee bend uses a heading-relative, fixed bend plane: `cross(-character_right, ankle-hip)`. This removes dependence on a world +X pole for turning characters. Joint reach/near-straight limits and frame displacement are checked; there is no general biomechanical muscle/joint solver. Torso counter-rotation and head lag use action-specific timing. The hierarchy contract includes explicit chest/neck positions rather than unrelated line transforms.

Stair contacts have immutable tread targets and independent swing intervals. A pressure/COM preview plan supplies horizontal body progression, while reach constraints bound height. Actual shoes rotate around toe anchors during heel lift. Stair geometry uses the same .30m run/.18m rise coordinates as contact tests. The clean shot is side-on; the diagnostic adds all joints, target crosses, contact state, tread indices and pelvis trajectory.

The key is full-length geometry. The leaf and cylinder have actual openings, and the slot rotates with the key. Key bow, fingers, cylinder, lever and door all have defined parent frames. The door hinge is fixed. The controller explicitly withdraws and stows the key before gripping the lever. Interior/exterior angles read the same state, not duplicate rigs.

Vehicle control is causal: fixed-step midpoint bicycle integration updates the rear axle and heading from speed and commanded steering. The car-body origin derives from that rear axle. Each tyre's rotation integrates its own centre's travel; front tyres use Ackermann angles. A damped body roll/pitch channel responds to lateral/longitudinal acceleration. Cockpit, hands, pedals, mirror projection and exterior derive from the same state. The pursuer integrates its own state with a lookahead steering controller. The city is built once around a sampled reference route, with fixed-world addresses and dimensions; its coordinates are not time-dependent.

The curtain uses a controlled fabric fold rig. Sliding top rings constrain the top edge to a fixed rail; each material row maintains its horizontal arc length while the visible width compresses into depth folds. Row delays and a damped release response prevent a rigid blind translation. It is not a general-purpose cloth simulation or full collision solve. The grabbing hand derives from the same edge vertex as the fabric.

The renderer consumes world-space geometry and performs perspective projection with a per-pixel depth buffer. Approved head geometry is retained; a reconstructed rear cap silhouette avoids drawing frontal eyes on a back view. Head orientation is derived relative to the camera and body; the curtain reaction supplies a genuine head-forward turn. Camera angles are fixed within interaction phases. Separate clean and diagnostic encoders consume the same newly rendered frame.

Background caches are disabled in these M03 shots. Every export records producer SHA-256 values, exact frame states (losslessly compressed JSON), source RGB hashes and MP4 hashes. `SOURCE_EDIT_RENDER_PROOF.json` demonstrates that editing a copied controller in an isolated source tree changes actual rendered pixels in fresh processes.

## Predictive body-trajectory repair

The initial M03 reach-envelope clamp was itself a defect: it could abruptly release a pelvis height limit while foot targets stayed fixed. `stabilize.py` plans the whole contact interval before rendering. It smooths horizontal root motion, computes future leg/attached-arm reach bounds, anticipates tighter height limits and solves bounded least squares with second/third-difference penalties. It then reconstructs IK around that root while preserving immutable feet, key and handle grips. SciPy is already installed and serves this explicit free optimization purpose. The solver does not simulate forces; it removes the measured 42/33 m/s² root spikes rather than concealing them with camera motion.
